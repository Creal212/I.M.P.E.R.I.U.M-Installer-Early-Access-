# 0.2.19 — The lighter installer and provider reliability update

Source-record date: **2026-09-24**.

**Unsigned early access — manual installation and updates.** [Download and verify](../docs/DOWNLOADS.md). Historical installers keep their original versions and notes.

## Recorded changes

- All four native models — Lite, Mini, Agent 589 and Core — are optional downloads in Settings → Agent 589. The installer no longer contains the 2.1 GB Granite weights or the 18.4 MB CPU engine archive.
- Fresh installs do not download, prepare or start native models. Choose Download files, then Start; the app obtains the pinned CPU engine only when an explicit Start needs it. Existing models, saved stops and earlier choices are preserved.
- Codex replies, function calls, reasoning continuation and measured usage retain the correct protocol across the shared tool-loop boundary, addressing completed replies that previously appeared empty.
- Codex subscription image generation and editing use a host-owned HTTPS adapter tied to the connected account. The app validates image bytes and applies artifact checks, without a native CLI, personal-drive access or API billing fallback.
- Workspace builds can generate fresh project images through the selected Codex subscription account. A visual prompt is the only model input to this tool; the host decodes and inspects returned bytes before adding a new asset for candidate review. General editing tools are not enabled merely by asking for an image. Existing files, account selection and Main patch gates remain protected; image editing and other Workspace image providers are not claimed.
- Provider selectors share short-lived project-scoped results and in-flight checks. Explicit account changes still refresh status, and actual task admission checks the selected connection again.
- Providers now offers an explicit Workspace permissions control for each connection profile: Read only or Read and edit. Existing read-only profiles stay read-only until the user saves a change; reconnecting, refreshing or choosing a model preserves that choice. Editing remains confined to assigned clone candidates, with Main changes reviewed separately.
- Empty submissions no longer substitute for conversational answers. Task limits and no-progress stops are reported as unfinished, while genuine generated files retain a host-written result summary and review path.
- Windows provider discovery avoids starting PowerShell for each user-environment lookup, performs independent subscription checks concurrently and retains other successful results when one detector fails.
- Supported task tool loops gain readable public HTTPS fetch and host-owned search. Selected Codex tasks use the same subscription account and model for a cited search, consuming its allowance; other supported models use DuckDuckGo's public HTML endpoint. Current Skills grants and a network-enabled mode are required. Direct fetch blocks local/private destinations and redirects, and extracts static text without executing page scripts. Results remain bounded, redacted and untrusted, with task receipts and explicit search usage accounting. No challenge bypass, account switch, automatic retry or paid API fallback is used.
- Supported command-free API connections and native requests that need tools use the shared host-scoped Studio/Blueprint tool path. Ordinary native companion chat keeps its measured text path. Inputs remain read-only, deliverables stay under the session's outputs area, and the selected provider/account is preserved; unsupported native CLIs are not enabled by this change.
- Workspace read-only requests can answer without an old State 0 record. Older projects can explicitly review the current clone as a Recovery baseline; actual edits and patch promotion retain baseline, sensitive-content and digest checks. Existing snapshots and Main remain unchanged.
- Native setup describes download size, memory fit, progress and errors. Only owned, authenticated, ready native models appear in task selectors; model availability is not a claim of coding-quality qualification.

## Data and provenance

Upgrades replace installed program files and preserve separate user data, projects, Main folders, downloaded models and saved choices. The small pinned Microsoft runtime dependency and required model/engine notices remain in the installer. WebView2 may still need internet if missing. After explicit model and engine setup, native inference can run offline.

Granite Lite is the restored baseline with known code/test failures, not a newly qualified model. Mini and regular coding-workflow qualification remains incomplete; Core has simulation-only evidence. No native-model auditions were resumed for this update. Host file scope, identity, memory, Change Review and rollback controls remain active.

## Validation scope

Six initial model-free web gateway fixtures and combined source compilation passed. A bounded live search through the selected Codex GPT-6-Luna subscription returned official Python documentation citations in 4.277 seconds, with provider-measured 8,514 input / 95 output tokens. Readable HTTPS fetch also passed; receipts were saved, the outside canary remained unchanged and the candidate stayed empty. Earlier DuckDuckGo HTTP 202 challenge, unsupported subscription field and insufficient search-context allocation failures remain recorded. This establishes one working account/query and one static fetch, not all providers, full Studio workflows or universal availability.

A live Codex subscription image smoke returned one PNG through the actual adapter; the image was decoded and visually inspected. This establishes one generation request, not editing, every account/plan, cancellation, or a complete Studio workflow. Final installer identity and the scoped regression results are recorded in the [0.2.19 status record](../docs/RELEASE_0_2_19_STATUS.md). Separate-device installation and every supported account or workflow remain unverified here.
