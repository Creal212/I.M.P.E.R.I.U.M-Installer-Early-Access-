## Recorded changes

- Workspace context shortlists no longer become file-access boundaries. Agents can discover dependencies and create permitted files across their assigned Clone while honoring explicit no-edit requests.
- Legacy projects without a trusted original State 0 can retain a separate current-Clone work checkpoint for agent edits and Undo. This does not invent an original baseline or enable Main patching before recovery.
- Registered agents retain ordinary Clone editing tools. Provider permission copy now explains the actual environment boundary instead of suggesting an obsolete read-only switch.
- Supported image tools work inside Workspace tasks and Studio/Blueprint output sessions through the selected Codex subscription or OpenAI, Gemini or xAI API connection. Actual returned files are inspected before delivery; account and billing routes stay bound to the selection.
- The selected xAI API connection can create a 6-second, 480p MP4 with its video model. Jobs are polled, locally stoppable and statically inspected. Live paid video generation was not tested; accepted remote jobs may continue and incur charges after Stop.
- Studio uses its selected connection and enabled tools instead of inheriting unrelated project offline settings. For local-only Studio work, choose an offline model and disable network tools. Blueprint retains its selected project policy.
- Named Google/Gemini API imports retain the correct route and selected credential; xAI API imports retain their API access classification.
- Agent 589 recognizes more visible panel, card, toolbar, editor and composer surfaces, can be placed on them, and follows layout changes while respecting hidden, quiet and reduced-motion preferences.

## Observed behavior and verification

A separate real GPT-6 Astra task created the exact requested 19-byte file, preserved its README and an outside-candidate canary, completed host verification and submitted in 14.051 seconds across four model turns. These used disposable data and the production transports; they are not full desktop or universal provider certification.

The first tiny-file fixture created the correct file but stopped before submission because its 32k task input allowance was too small for the full tool sequence. A bounded rerun used the existing build-fixture allowance, with no production guard relaxed. Tool-only completion is presented through the host's actual finalization report, not invented model prose.

Focused image tests: 56 provider tests, 10 gateway tests, one named-provider-route regression and one Studio output-scope regression passed. Frontend checks passed 81 tests across eight files; 49 desktop Studio command tests, 45 focused clone/task tests and all 79 artifact tests passed. The artifact suite includes raw MP4 scanning and quarantine. Video fixtures passed 8 Studio adapter tests and 7 gateway tests. A stale Studio test helper was updated to parse the current guidance wording; this was a test mismatch, not an additional production defect. Package evidence is recorded in the linked verification document. xAI video uses protocol/container fixtures; **live xAI video was NOT RUN**.

## Upgrade and limits

This remains unsigned early access with manual updates. Main, private vault data and unrelated local files remain outside agent authority. The system applies reviewed patches to Main; agents do not receive a general-purpose host shell. Claude, Gemini and Grok native CLI subscription execution remains unavailable where this app cannot verify filesystem containment. A connected account or powerful text model does not itself create an unsupported image/video transport. Offline modes and explicit tool opt-outs still apply.

No new native model or portable package is bundled. Lite, Mini, Agent 589 and Core remain optional Settings downloads. The historical 0.2.15 Mini preview is unchanged. Fresh physical-device installation, real-data upgrade behavior and general model coding quality are NOT EVALUATED by these focused checks. Static inspection is not a malware, visual-content or functional-safety guarantee.

Save work and keep backups before updating. Program-file replacement is separate from saved projects, model files and settings; this is not a newly verified real-data migration guarantee.
