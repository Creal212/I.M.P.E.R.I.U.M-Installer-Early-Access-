# 0.2.18 — The guided-build and native setup update

Source-record date: **2026-09-24**. This records the development note date, not a public upload date.

**Prepared package — public download not confirmed.** Continue using the latest published installer in [Downloads](../docs/DOWNLOADS.md) until this version is published. Earlier packages retain their own versions in the [Historical installers archive](../docs/INSTALLER_ARCHIVE.md).

## Recorded changes

- Four native tiers are presented clearly: Lite, Mini, Agent 589 and Core. Granite 4.0 Micro returns as the included Lite baseline; the larger models are optional manual previews. Heavy is removed from the current lineup.
- Native setup keeps background progress, pause/resume and visible errors. Downloads verify exact artifact identity; installed files appear in task selectors only after their owned runtime is ready. Starting another native confirms shutdown of the current app-owned one; downloading alone does not switch it.
- The installer includes the exact Granite Lite weights and CPU engine, plus a skippable choice of larger-model downloads. If Microsoft Edge WebView2 is missing, installation needs internet for its embedded bootstrapper. Native inference can run offline after preparation. Memory guidance uses RAM available for AI plus separate host headroom; existing paused/stopped preferences and older models remain distinct.
- Earlier native versions appear in collapsed retained history only when their files, session or saved setup exists. Uninstalled retired models are not offered as fresh downloads, and conversations are not silently moved to another provider.
- Provider/model choosers refresh after account changes and imports, retain the selected pair, and distinguish a missing runtime or uncertain status from a confirmed sign-out.
- Saved clarification questions in Workspace, Studio and Blueprint support suggested or free-text answers and recovery after reopening. Waiting for an answer is not task completion; continuation keeps the existing permissions and remaining budget.
- Focused Builder retains direct replies, exact code/JSON and completed work across clarification. Smart Solo reuses completed advice without charging it twice. Completed exports are retained, while a later answer can still request a new export.
- Supported document adapters retain the original attempt and permit one explicit format correction within the aggregate task budget. Empty, partial or refused replies remain visible failures; provider settings, roles and supplied usage accounting stay attached to the attempt.
- Shared guidance answers obvious tasks and asks for consequential missing details. Native build context stays focused on the task; measured reply allocation preserves the current request and corrections. Imported capacity uses the selected connection's reported limits and conservative defaults when unknown.
- Structured history separates earlier messages from the current task, redacts references before sealed persistence, and fits whole-message history without deleting the saved conversation. Omission notices remain explicit. Scoped model-free backend and desktop checks have passed. Live-provider compatibility and physical-device installation remain separate.
- File-edit tools distinguish each target from its complete contents. The host validates arguments and does not execute model-written JSON prose. Local Python syntax diagnostics and one bounded host-quality correction help surface and respond to confirmed issues without expanding permissions or budgets.
- A separate host-verification notice beside a final Workspace reply identifies blocked or unverified changes, bound to that task and project. Model wording is preserved; a confident answer does not override recorded checks.
- A clone-only environment setup guide lists empty variable names and feature/API requirements. Original environment configuration is excluded during import; environment-file changes and generated guides are independently kept out of Main patches.
- Native launch/recovery binds exact model and owned process identities, verifies model/engine files, checks available memory, and uses hidden Windows process cleanup. Setup failures persist visibly. Provider errors preserve useful bounded diagnostics without exposing credentials or raw error pages.
- Offline Settings includes exact native-model provenance, retained legacy notices and the original tree-sitter/Python MIT licenses. Existing tool scope, Change Review, patch and rollback boundaries remain in force.
