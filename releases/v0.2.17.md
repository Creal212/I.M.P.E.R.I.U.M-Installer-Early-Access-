# 0.2.17 — The Obsidian and Parchment update

Source-record date: **2026-09-23**. This is the date recorded in the publisher's note, not an inferred public upload date.

**Published early access — Windows x64, unsigned, manual updates.** [Download and verify 0.2.17](../docs/DOWNLOADS.md) or read the [versioned GitHub release](https://github.com/Creal212/I.M.P.E.R.I.U.M-Installer-Early-Access-/releases/tag/v0.2.17). Earlier installers are kept in the [separate archive](../docs/INSTALLER_ARCHIVE.md).

## Recorded changes

- Home gains the Project Compass: Plan, Build and Review open Blueprint, Workspace and Projects, with themed seal and helmet artwork and numbered start cards.
- A consistent visual refresh covers navigation, project cards and details, Workspace tools, Studio and Blueprint, activity, security, patches, receipts, provider setup, Settings, imports and dialogs.
- Obsidian Dark pairs mineral charcoal with copper; Parchment Light pairs warm paper with oxblood. Saved theme choices, fonts and motion preferences remain compatible, with theme colors applied before the initial screen.
- Separate Studio and Blueprint histories, clearer conversations and composers, an activity timeline, readable forms and consistent keyboard focus make working areas easier to follow. Existing permissions, project evidence and review gates continue to determine what actions are allowed.
- Includes the saved response/context and startup improvements recorded under the source-only 0.2.16 milestone. No 0.2.16 installer was published.
- Workspace, Studio and Blueprint share guidance for obvious pasted tasks, ambiguous requests, missing evidence and exact requested output. Imported models retain their provider settings and actual capability limits.
- Empty or incomplete Studio/Blueprint replies report a recoverable error and preserve the original draft. Reasoning-only, filtered and context-truncated replies are not shown as completed answers.
- Context fitting preserves code indentation, requested output whitespace and the latest user correction. Missing attachment contents and unavailable tools are identified without claiming access or completed work.
- Activity stays visible outside the scrolling conversation and can be closed or reopened. Draft instructions and pending controls survive visibility changes; delayed acknowledgements do not erase newer typing.
- Native startup checks current free memory and installed model size, explains shortages, shows animated readiness progress, prevents duplicate starts and avoids reporting stopped models as ready. Another model is never stopped automatically to make space.
- Offline Privacy & policies in Settings includes Axiom Risk contact details, data handling, AI-use guidance, installer terms and supplied third-party notices. These notices are not legal certification.
- Updated primary-button contrast, theme-aware status surfaces and reduced-motion support accompany the new themes.

## Data and provenance

This is the Windows x64 early-access installer following 0.2.15. The installer, checksum file and validation record were published on 23 September 2026. GitHub's uploaded sizes and SHA-256 digests match the verified local files. It is not Authenticode-signed and has no updater signature; updates are manual.

Normal upgrades replace application binaries and resources while preserving user data, Main projects and scratch work. Save work, close the app and keep independent backups before upgrading.

Native Mini retains the pinned bundled model/runtime. No experimental model candidate or developer evaluation data is part of this release. Regular and Core remain optional, subject to their hardware and runtime requirements. Native-model quality evaluation is incomplete; these interface and reliability changes do not qualify every model or imported provider.

Local visual and component checks do not establish fresh-device installation, every provider workflow or universal AI-output reliability. Early-access and experimental Shadow Verify limitations remain.

The [0.2.17 verification record](../docs/RELEASE_0_2_17_STATUS.md) separates completed source, package, bounded startup and public-upload checks from broader workflow qualification. The fresh-profile startup check ran without starting a model.
