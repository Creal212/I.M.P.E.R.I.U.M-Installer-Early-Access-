## Changes

- Pause, Resume, Steer and Stop have distinct behavior in Workspace, Studio and Blueprint. Supported host-controlled sessions pause at a safe boundary and resume the same task with its recorded context and completed work retained.
- Steering is shown as pending until the host acknowledges it. It updates the active task at a safe boundary; unstarted proposals from the older instruction are deferred. A paused task remains paused until Resume.
- Stop remains available while Pause is pending. Late responses from an older task, project or conversation cannot overwrite the visible controls or clear a newer draft; parallel tasks keep their own live replies.
- Simple conversational prompts no longer require a build submission merely because clone editing is available. Host-controlled tool requests account for their actual provider request shape, reducing premature input-budget failures.
- Continued work keeps its remaining execution budget. Recorded upfront Studio operations are reused across a steering or publication retry instead of automatically repeating paid media generation.
- Task reports distinguish requested controls, acknowledged state and retained output. Settings policy text explains safe-boundary pauses and the limits of stopping a request already sent to a provider.
- The mandatory release regression gate now includes named task-control, steering, budget and cross-conversation tests alongside the existing clone/Main and output safeguards.

## Limits and upgrade

Unsigned early access with manual updates. Main and unrelated local files remain outside agent authority; only the app applies reviewed patches to Main. Native models remain optional Settings downloads; this installer bundles no model or new portable edition. Existing user settings remain in effect.

Pause takes effect at the next supported boundary, so an in-flight provider request may finish first. Stop cannot undo completed work or guarantee that a remote provider avoids a charge. Unsupported external worker transports retain their documented checkpoint/restart behavior. A late correction received during final verification may require a follow-up or explicit Resume.

These repairs do not qualify every provider or improve a model's intrinsic coding ability. No new live model inference, paid-provider request, fresh physical-device installation or real-data migration is claimed unless separately recorded in final verification evidence. Existing image, archive and scan limitations remain documented in earlier releases. The historical 0.2.27 installer and 0.2.15 Mini preview keep their original identities and limitations.

Save work and keep backups before updating. Program files are replaced separately from saved projects, settings and optional model files. This is not a newly verified real-data migration guarantee.
