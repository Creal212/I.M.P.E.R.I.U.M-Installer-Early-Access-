# Getting started

## Install and choose a model

Read [Downloads](DOWNLOADS.md) for the exact version, checksum and signing status. A repository archive is not the app. The installer targets Windows x64; suitable Windows/WebView2 support, storage and model hardware are needed. Save work, close the app before upgrades and keep independent backups.

Granite Lite weights and the CPU engine are included. If Microsoft Edge WebView2 is missing, installation needs internet for its embedded bootstrapper. Lite is then prepared from the included files on first launch when no saved setup choice overrides it. Wait for verified readiness; if setup fails, the native-model page retains the error and recovery action. Model files, engine ready and AI responding are separate states. Open **Providers** or **Agent 589** to review readiness or manually choose a larger preview. Native inference can run offline once prepared. See [hardware and model limits](HARDWARE_AND_MODELS.md); all generated work still needs review.

For an external connection, follow its supported account/API setup. Some routes need the provider's own runtime or account configuration. Login does not guarantee task execution or media entitlement. Keep account codes and keys private, then choose the provider and model in your working environment.

## Import or create

1. Import a folder/ZIP you are authorized to use, or create a new project.
2. Review inspection findings and excluded material. Approving sensitive material is an explicit choice; automated coverage has limits.
3. Let the app prepare the separate Clone and initial saved state. If import fails, follow its recovery message; do not delete Main.
4. Open Workspace and confirm the project, provider and model.

Describe the intended result and relevant requirements. Attach only material you intend to share. Specific acceptance criteria help, but clear exercises do not require special command syntax. Check the task report when work fails or stops; a model's acknowledgement is not completion.

## Review and apply

Inspect changed files in the Clone. Keep or revert work, create a named patch and review its contents, prerequisites and checks. Applying that patch to Main is a separate action.

Applied history and rollback are distinct from restoring the current Clone. Inspect the rollback preview, especially when later edits overlap. A rollback may require conflict review and is not a backup system.

## Studio, Blueprint and help

**Studio** works with conversations and supplied attachments. Real generated files appear as attachments; a filename in model text is not a download.

**Blueprint** develops an outcome, requirements and plan before handing reviewed work to Workspace. It keeps a separate planning history.

Use available help/information controls to replay or skip guides. Click the platform name for its linked overview.

For trouble, check provider readiness, exact errors and retained task reports. Follow hardware guidance rather than forcing simultaneous model startup. [Support](SUPPORT.md) explains what to share safely.
